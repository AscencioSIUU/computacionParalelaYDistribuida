01 · Introducción

¿Qué se va a realizar?

Una simulación de un sistema simplificado de predicción de condiciones climáticas para el día siguiente, sobre 500 regiones, cada una con sus condiciones actuales.

El objetivo real no es un sistema meteorológico preciso, sino estudiar la paralelización con OpenMP.

Entrada

  • Temperatura actual
  • Humedad actual
  • Viento actual

Salida

  • Temperatura siguiente
  • Humedad siguiente
  • Viento siguiente

04 · Modelo de predicción

Modelos lineales simplificados

Las condiciones futuras dependen linealmente de las actuales:

Tsig = a₀ + a₁·Tact + a₂·Hact + a₃·Vact
Hsig = b₀ + b₁·Tact + b₂·Hact + b₃·Vact
Vsig = c₀ + c₁·Tact + c₂·Hact + c₃·Vact

Los coeficientes a, b, c son los parámetros del modelo.

05 · Justificación

¿Por qué un modelo lineal?

El objetivo es estudiar programación paralela, no la precisión meteorológica.

Sencillo

Fácil de implementar y de relacionar varias variables.

Buena carga

Produce muchas operaciones repetidas para las 500 regiones.

Independiente

Cada región se calcula por separado → paralelismo de datos directo.

08 · Pseudocódigo secuencial

El bucle base

// sumas ← 0 ; iniciar temporizador
PARA i ← 0 HASTA N-1
    tempSig[i]   ← calcularTemperatura(temp[i], hum[i], viento[i])
    humSig[i]    ← calcularHumedad(temp[i], hum[i], viento[i])
    vientoSig[i] ← calcularViento(temp[i], hum[i], viento[i])

    sumaTemp   ← sumaTemp   + tempSig[i]
    sumaHum    ← sumaHum    + humSig[i]
    sumaViento ← sumaViento + vientoSig[i]
FIN PARA
// detener temporizador ; promedios = suma / N

10 · Paralelismo de datos

#pragma omp parallel for

En vez de un thread procesando las 500 iteraciones, OpenMP reparte las iteraciones entre los threads disponibles. Cada thread ejecuta el mismo algoritmo sobre regiones distintas.

Thread 0regiones asignadas → predicción
Thread 1regiones asignadas → predicción
Thread 2regiones asignadas → predicción
Thread 3regiones asignadas → predicción

11 · Paralelismo de tareas

#pragma omp sections

Otra división: en lugar de repartir regiones, repartir tipos de trabajo. Cada sección se asigna a un thread distinto.

Section 1

Todas las temperaturas

Section 2

Todas las humedades

Section 3

Todos los vientos

PARALLEL SECTIONS
  SECTION  PARA i: calcular tempSig[i]
  SECTION  PARA i: calcular humSig[i]
  SECTION  PARA i: calcular vientoSig[i]
FIN

12 · Comparación de estrategias

Datos vs. tareas

Paralelismo de datos

Cada thread toma algunas regiones y calcula para ellas temperatura + humedad + viento.

T0 → regionesT1 → regiones

Paralelismo de tareas

Cada thread hace un tipo de trabajo sobre todas las regiones.

T0 → temperaturasT1 → humedades

13 · Manejo de variables

Cláusulas de OpenMP

CláusulaComportamiento
shared(x)Todos los threads acceden a la misma variable/memoria
private(x)Cada thread obtiene su propia copia (sin inicializar)
firstprivate(x)Copia propia inicializada con el valor original
reduction(+:x)Sumas parciales por thread, combinadas al final

Los arreglos son shared (todos acceden), pero cada thread modifica índices distintos; las variables temporales son private.

14 · El problema

Condición de carrera

Al acumular sumas en una variable compartida, varios threads la modifican a la vez.

Con suma = 10, T0 suma 5 y T1 suma 7. El resultado correcto es 22, pero si ambos leen 10 antes de escribir, uno sobrescribe al otro → resultado incorrecto.
Thread 0
Thread 1
Thread 2
Thread 3
↓ todos a la vez ↓
sumaTemperatura ⚠

15 · La solución

reduction(+: suma)

Cada thread acumula en una suma parcial independiente; al final de la región paralela OpenMP las combina — sin condiciones de carrera.

T0 → parcial 0 T1 → parcial 1 T2 → parcial 2 T3 → parcial 3
→ SUMA FINAL

16 · Pseudocódigo paralelo

Todo junto

PARALLEL FOR
  shared(temperatura, humedad, viento, resultados)
  private(variablesTemporales)
  firstprivate(parametrosIniciales)
  reduction(+: sumaTemp, sumaHum, sumaViento)

  PARA i ← 0 HASTA N-1
      calcular tempSig · humSig · vientoSig
      acumular temperatura · humedad · viento
  FIN PARA
FIN PARALLEL FOR
// detener temporizador ; calcular promedios

17 · Estadísticas

Promedios con reduction

Tprom = ΣTsig / 500
Hprom = ΣHsig / 500
Vprom = ΣVsig / 500

También sirven para verificar que la versión secuencial y la paralela producen resultados equivalentes.

18 · Rendimiento

Speedup

Cuántas veces más rápida es la versión paralela respecto a la secuencial.

Sp = Ts / Tp

Ts = tiempo secuencial · Tp = tiempo paralelo

Ejemplo

Ts = 8 s   ·   Tp = 2.5 s

Sₚ = 3.2×

≈ 3.2 veces más rápida que la secuencial.

19 · Rendimiento

Eficiencia

El Speedup no dice qué tan bien se usan los threads. La eficiencia sí.

Ep = Sp / p

p = cantidad de threads

Ejemplo

Sₚ = 3.2   ·   p = 4

Eₚ = 80 %

3.2 / 4 = 0.8 → aprovechamiento de los 4 threads.

21 · Consideración clave

Más threads ≠ más rendimiento

OpenMP añade costos: creación de threads, distribución del trabajo, sincronización, acceso a memoria compartida y combinación del reduction.

Con solo 500 registros y cálculos pequeños, el costo de administrar threads puede igualar o superar al cálculo: Tp ≥ Ts y Sp ≤ 1. No es un error — el problema puede ser demasiado pequeño.

La verdadera pregunta

¿Cuándo vale la pena paralizar este problema?

La experimentación revela si el costo del cálculo justifica los múltiples threads.
